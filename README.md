# 🐾 わんわんパーティー ― 2人専用オンラインミニゲーム集

ホスト1人とゲスト1人で遊ぶ、ブラウザだけで動くオンラインミニゲーム集です。
最初のゲームは **「わんわん爆走カート」**。柴犬（ホスト）とコーギー（ゲスト）が小さなカートに乗り、
アイテムと体当たりで邪魔し合いながら3周レースで勝負します。

- サーバー不要（GitHub Pages などの静的ホスティングで公開できます）
- 2人の通信は WebRTC（PeerJS）の P2P。接続の仲介だけ PeerJS Cloud を使います
- ログイン・アカウント・APIキー・データベースは不要です

---

## 1. ゲームの概要

### 画面の流れ

① 接続 → ② ホーム → ③ ゲーム選択 → ④ 準備 → ⑤ ゲーム → ⑥ 結果 →（③へ戻る）

| 操作 | ホスト | ゲスト |
|---|---|---|
| 部屋を作る | ○ | – |
| 招待URLから参加 | – | ○ |
| ゲームを選ぶ / 中止する / 結果から戻る | ○ | × |
| 準備完了・取り消し | ○（自分のみ） | ○（自分のみ） |
| 一時停止したゲームの再開 | ○ | × |
| 部屋の解散（確認ダイアログあり） | ○ | × |
| 部屋から退出（ゲスト枠を空ける） | – | ○ |

### わんわん爆走カート

- 3周レース。チェックポイントを順番に通らないと周回になりません（逆走・ショートカット対策）
- **コースは10個**（準備画面でホストが選択、または 🎲 ランダム。どれも 1 周およそ 2500〜3000 で、以前の約2倍の長さです。
  曲がり方も作り直し、小刻みなS字・切り返し・大きな回り込みが続きます）
  - 🌼 わんわん草原サーキット: 長いストレート・ヘアピン・S字
  - 🏖️ しっぽフリフリ海岸: 砂浜の島。海ぞいの長いストレートと、うねる浜辺の道
  - ❄️ もこもこ雪山: 切り返しの多いテクニカルコース（雪が舞います）
  - 🍁 ひらひら紅葉の森: 落ち葉色の森。大きな丘と細かく曲がる山道
  - 🌃 きらきら夜のスタジアム: 暗い夜空の下の、広い直線と連続カーブ
  - 💎 ひんやり水晶の洞窟: 光る水晶の洞窟。トンネルが3か所
  - 🚇 ガタゴト地下鉄トンネル: 街の地下。コースのほとんどがトンネルの中
  - 🌋 ぐつぐつ火山: 溶岩が流れる火山。山の中を貫くトンネルを2回くぐります
  - 🏜️ からから砂漠の大砂丘: 砂丘をぬう長いコース。岩のアーチトンネルをくぐります
  - 🍭 ふわふわおかしの国: キャンディの渦まき。チョコレートのトンネルをくぐります
  - **トンネル**: 中に入ると暗く、霧が近づき、雨も降りません（ランプの光が目印）。ミニマップでは暗い線で表示します。
    道路は平らなままで、地下へ下る坂や立体交差はありません（見た目と明るさだけの演出です）
- 🍖 **ドッグフード**: 道に落ちている粒（1周に125個）。拾うと最大15個まで持てて、**多く持っているほど最高速が少し上がります**（1個あたり +0.4%、15個で +6%）。
  持てる上限のときは拾わずに通り過ぎます。相手にぶつけられてスピンすると3個落とします（ガードで防げば落としません）。
  拾われても16秒でまた出ます。画面左下に所持数を表示
- 👑 **ボス犬（ドーベルマン）**: かなり強い NPC を1台追加できます（準備画面の「ボス犬」。既定は出す）。ふつうの NPC より速く、
  カーブの減速が少なく、タイミングブーストをジャストで決め、ホネ・フリスビーを外さないよう近づいてから使います。
  人間との差が大きく開いたときだけ少し手加減します。ゴールしても勝敗には関係しません（順位には入ります）
- 🏆 **連戦**: 準備画面で「1レースだけ / 2・3・4・6連戦」を選べます。1レースごとに結果画面でポイントを表示し、ホストが「次のレースへ」を押して続けます。
  最後に合計ポイントの高いほうが**シリーズ優勝**。コースを 🎲 ランダムにすると、連戦の中でまだ使っていないコースから選びます
  - 順位ポイント: 全員（NPC・ボス犬を含む）の中での順位で 15 / 12 / 10 / 8 / 6 / 4 / 2 / 1
  - ドッグフード 1個につき 1 点・体当たり成功 1回につき 2 点・アイテム命中 1回につき 3 点
  - ファステストラップ: ベストラップが2人のうち速かったほうに 5 点
- ⚡ **タイミングブースト**: 1レースに1〜2回（ランダム）、コースの途中でリングが出ます。
  外側のリングが縮んで真ん中の的に重なった瞬間に**画面をクリック / タップ（または Enter）**するとブースト。
  ぴったりなら「ジャスト！」で長め、少しずれると「ナイス！」で短め、大きくずれると無し（チャンスは1回押すと終わり）
- 🟨 **ブーストパッド**: 路面の光る矢印（1周に10枚）を踏むと、踏んでいる間ブーストして加速します。NPC も使います
- アイテムボックスは6か所に横5列。取るとルーレットのあとアイテムが1つ手に入ります（同時に1つまで）。
  アイテムを持っている間・ルーレット中はボックスをすり抜けるので、1人が箱を割って総取りすることはできません
  - 🦴 **ホネアタック**: 前方に骨を投げる。当たると相手がスピン（壁で跳ね返るので自爆注意）
  - 🍌 **バナナトラップ**: 後ろに置く。踏むとツルッとスピン（一定時間で消える）
  - ⚡ **わんわんブースト**: しばらく超加速
  - 🛡️ **ガード**: 泡に包まれ、ホネ・バナナ・フリスビー・体当たり・豪雨のどれか **1回だけ** 防ぐ（使って20秒で消える。犬小屋だけは防げません）
  - 🥏 **フリスビー**: すぐ前の順位の相手へ、**コースに沿って**飛んで当てる（カーブも曲がり、壁にぶつかって消えません。飛べる距離に限りあり）。**2位以下**だけが引ける
  - 🧑 **飼い主登場**（マリオカートのキラー）: 約6秒、飼い主に引っぱられて**無敵・自動操縦で超高速**に走る。触れた車ははね飛ばされ、ホネ・バナナは効きません。**後ろの順位ほど出やすく**、先頭は引けません
  - ☔ **豪雨**: **最下位（NPC を含む全員の中でビリ）**の車だけが引けるアイテム。使うと雨雲が出て、使った車以外が5秒ほど最高速が下がります（ガードで1回防げます）。NPC も使います
  - 🏠 **犬小屋**: **2位以下**だけが引ける。使った時点の**1位の頭上へ必ず落ちます**（約2.2秒、落下地点の赤い輪が1位を追いかけ、落ちる瞬間にその範囲＝約9mの車も巻き込みます。使った本人が近くにいれば巻き込まれます）。スピン直後の無敵も無視し、**ガードでも防げません**（ガードは割れます。飼い主モード中の車だけは無敵）。自分が1位のときに使うと不発です
  - 出る確率は順位で変わります: ガードは最下位以外、フリスビーと犬小屋は2位以下、豪雨は最下位だけ、飼い主登場とブーストは後ろほど出やすい
- 車同士がぶつかると押し合い、速度差が大きいと相手が跳ね上がる「ドカーン!」演出
- スピンの後は短い無敵時間があり、ハメ続けられないようになっています
- **NPC（コンピューターの犬）**: 準備画面でホストが「なし / 1〜4台」を選べます（既定は2台。プードル → パグ → ダックス → ハスキーの順に増えます）。ボス犬は別枠で最大1台追加されます。
  NPC もアイテムを使い、体当たりもしてきます。人間との差が開きすぎると手加減・追い上げをします
- 順位は NPC を含めた全員の中で表示。**勝敗はホストとゲストのどちらが先に3周したか**で決まります（NPC が先にゴールしてもレースは続きます）
- 結果画面に総合順位・タイム・ベストラップ・体当たり回数・着順などを表示
- **カメラ**: いつもの三人称（後ろから）と、運転席の犬の目線の一人称を C キーか画面右上の「🎥」ボタンで切り替え（自分の画面だけ・設定は保存）
- **BGM**: メニュー用とレース用のオリジナル曲を Web Audio で演奏（ファイナルラップでテンポアップ）。🎵 ボタンで効果音とは別にオン/オフ

### 操作方法（PCキーボード）

| キー | 動作 |
|---|---|
| W / ↑ | アクセル |
| S / ↓ | ブレーキ・低速時はバック |
| A / ← | 左に曲がる |
| D / → | 右に曲がる |
| Space | アイテムを使う |
| R | 最後に通ったチェックポイント付近へ復帰 |
| C | カメラ切り替え（三人称 / 一人称） |

| Esc | （ホストのみ）一時停止 |

### 操作方法（スマホ・タブレット）

画面を触ると自動でタッチ操作に切り替わります（iPhone / iPad / Android の横向きが遊びやすいです。縦向きも遊べます）。

| 操作 | 動作 |
|---|---|
| 左下の ◀ ▶ | ハンドル（指を滑らせて切り替えもできます） |
| 右下の ブレーキ | ブレーキ・バック（既定は **オートアクセル** なのでアクセルは自動） |
| 🚗 オート | オートアクセルの ON / OFF（OFF にすると「アクセル」ボタンが出ます） |
| アイテムの丸いボタン | アイテムを使う |
| ↺ 復帰 | 最後に通ったチェックポイント付近へ復帰 |
| 画面のボタン以外をタップ | タイミングブースト（リングが出ているとき） |
| 🎥 / ⚙ 画質 / ⛶ 全画面 | カメラ切り替え / 画質の切り替え / 全画面（iPhone の Safari には全画面はありません） |

### 画質と軽量化

- 描画解像度・影・景色の密度は端末に合わせて自動で決まります（スマホは解像度 ×1・影は小さめ・木や雲を少なめ、タブレットは ×1.25）。
  描画が重いときは、解像度 → 影 → さらに解像度の順に**自動で下げます**。⚙ 画質ボタンで「自動 / 高 / かるい」を選べます（設定は端末に保存）
- 描画は最大 60fps（120Hz の iPad Pro などでは 1 フレームおきに描き、電池と発熱を抑えます）
- 壁のブロックは画面外のかたまりを描かない作りにしました（以前は 1 画面あたり約 70 万ポリゴンだったものが大幅に減ります）
- ゲーム中は画面が暗くならないようにしています（対応ブラウザのみ）

## 5. 遊び方

1. ホストが「部屋を作る」を押す
2. 表示された招待URLを「コピー」してゲストに送る（LINE・Discord など）
3. ゲストがURLを開くと自動で参加し、2人ともホーム画面へ
4. ホストが「ゲームを選ぶ」→「わんわん爆走カート」を選ぶ
5. 準備画面で2人とも「準備完了！」を押すと、カウントダウン後にレース開始
6. 3周したほうの勝ち！ 結果画面からホストが「ゲーム選択へ戻る」で次の勝負へ

## 6. ホストとゲストの接続手順（詳細）

- 部屋IDと招待シークレットは Web Crypto API の乱数で作られ、招待URLのクエリ（`?room=…&key=…`）に入ります
- ゲストが初めて参加すると、ホストが **再参加トークン** を発行し、ゲストのタブの sessionStorage に保存されます
- ゲスト枠が埋まっている間は、正しい再参加トークンを持つ本人しか入れません（3人目は「この部屋はすでに2人そろっています」と表示）
- ゲストが同じタブでページを更新すると、保存されたトークンで自動的に元の部屋へ戻ります
- ゲストが戻ってこない場合、ホストはヘッダーの「新しいゲストを招待」でゲスト枠を空けられます

### 通信が切れたとき

| 状況 | 動作 |
|---|---|
| ゲーム中にゲストの通信が切れた | ホストが検出してゲームを一時停止し、切断直前の状態に巻き戻して保持。ゲストは自動で再接続し、状態を受け取って復元 → ACK → ホストに「ゲーム再開」ボタン → 3・2・1 で再開 |
| ゲストがページを更新 | sessionStorage の情報で自動再参加。ホーム/選択/結果は同じ画面、準備画面は準備状態をリセット、ゲーム中は状態を復元して再開待ち |
| ホストのシグナリング（PeerJS サーバー）だけ切れた | P2P のデータ通信が生きていればゲームは続行。裏で再接続を試みる |
| ホストがページを更新・閉じた | 以前の部屋は終了（復元対象外）。ゲストには部屋の終了が表示され、接続画面へ戻れる。通知が届かなかった場合もゲストは一定時間（約60秒）再接続を試みたあと「復帰できない」と表示 |
| ホストのタブが非表示になった | 描画ループが止まるため、ゲームを自動で一時停止（戻ってから再開） |

再接続待ちに時間制限はありません。ホストはいつでも「ゲームを中止」または「部屋を解散」を選べます。

## 7. GitHub Pages への公開手順

このリポジトリには GitHub Actions のワークフロー（`.github/workflows/deploy.yml`）が含まれています。

1. GitHub にリポジトリを作成してこのコードを push する
2. リポジトリの **Settings → Pages** を開き、**Build and deployment → Source** を **「GitHub Actions」** にする
3. リポジトリの**既定ブランチ**に push する（または Actions タブから「Deploy to GitHub Pages」を既定ブランチで手動実行）
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

補足:

- `vite.config.js` の `base: './'`（相対パス）により、`/<リポジトリ名>/` のようなサブパスでもアセットを正しく読み込めます。
  絶対パスにしたい場合は `BASE_PATH=/<リポジトリ名>/ npm run build` のように指定できます
- 招待URLは「現在のページのURL」を基準に `URL` オブジェクトで組み立てるため、サブパス配信でも正しいURLになります
- 画面遷移は独自パスではなくクエリパラメータだけを使うので、ページを更新しても 404 になりません
- 秘密情報（APIキー等）は使っていません。PeerJS Cloud はキー不要です
- ワークフローは既定ブランチ（Settings → General の Default branch）への push のときだけ公開します。
  GitHub Pages の環境は既定で既定ブランチからのデプロイだけを許可するためです

### Cloudflare の中継で通信する（任意・無料）

既定ではホストとゲストが **P2P（WebRTC）** で直接つながり、最初の出会いだけ PeerJS Cloud を使います。
会社・学校・一部のモバイル回線などでは直接つなげないことがあるため、**Cloudflare Workers + Durable Objects の中継サーバー**（`worker/relay/`）でつなぐこともできます。
カード登録なしの無料プランで動かす想定です（Cloudflare の無料枠: Durable Objects は 1 日 10 万リクエスト・実行時間 13,000 GB-秒まで。
受信メッセージは 20 件で 1 リクエストと数えられるため、2 人対戦（毎秒およそ 60 件）で全部あわせて **1 日 9 時間ほど**の対戦が目安です。超えると、その日は中継が使えなくなります）。

- 中継を設定すると、ホストは**まず中継で部屋を作り、使えなければ自動で PeerJS Cloud（P2P）にします**。招待 URL の部屋 ID が `wwr-` なら中継、`wwk-` なら P2P です（ゲストは URL だけで自動的に同じ方式につながります）。
- 中継は通信の中身を見ず、保存もせず、そのまま相手へ渡すだけです。ただし P2P より少し遅れが増えます（経由するぶんだけ）。
- 設定した Worker は `ALLOWED_ORIGINS`（`worker/relay/wrangler.toml`）に書いたサイトのページからしか使えません。ゲームを公開するドメインに合わせて書き換えてください。

**設定の手順（Cloudflare の画面だけで済みます）**
1. [Cloudflare](https://dash.cloudflare.com/sign-up) に無料登録し、**Workers & Pages → 作成 → GitHub のリポジトリをインポート**でこのリポジトリを選ぶ（プロジェクト名は `worker/relay/wrangler.toml` の `name`（`kusoge`）と同じにする）
2. プロジェクトの **設定 → ビルド** で、**ルートディレクトリ** を `worker/relay`、**ビルドコマンド** を空、**デプロイコマンド** を `npx wrangler deploy` にして、再ビルドする
3. 成功すると `https://kusoge.<サブドメイン>.workers.dev` が使えるようになる。ブラウザで開いて `{"ok":true,...}` と出れば動いています
4. このリポジトリの Settings → Secrets and variables → Actions → **Variables** に `RELAY_URL` としてその URL を登録し、Pages のデプロイをやり直す

手元でビルドするときは `VITE_RELAY_URL=https://…workers.dev npm run build` です。ローカルで試すだけなら、`worker/relay` で `npx wrangler dev` を動かし、`VITE_RELAY_URL=http://127.0.0.1:8787` でビルドします。

### 自前の PeerServer を使う場合（任意）

PeerJS Cloud の代わりに自分の [PeerServer](https://github.com/peers/peerjs-server) を使う場合は、ビルド時に環境変数を指定します。

```bash
VITE_PEER_HOST=peer.example.com VITE_PEER_PORT=443 VITE_PEER_PATH=/ VITE_PEER_SECURE=true npm run build
```

## 8. 新しいミニゲームの追加方法

共通システム（接続・部屋・画面遷移・準備・再接続・状態同期・中止・解散）はそのまま使えます。ゲーム側で必要なのは次の2つだけです。

1. `src/games/<ゲーム名>/index.js` を作り、`createGame()` を export する
2. `src/games/registry.js` の `GAMES` に1件追加する

```js
// src/games/registry.js
{
  id: 'quiz',                     // 英数字・_・- のみ
  title: '早押しわんわんクイズ',
  emoji: '❓',
  tagline: 'カード上の短い説明',
  description: '準備画面に出る説明',
  players: '2人対戦',
  controls: [['Space', '早押し']],
  tips: ['ルールの補足'],
  // 任意: ホストが準備画面で選べる設定。選んだ値は context.options で受け取れる
  options: [{ key: 'rounds', label: '問題数', choices: [{ value: 5, label: '5問' }, { value: 10, label: '10問' }], default: 5 }],
  load: () => import('./quiz/index.js'), // 選ばれたときだけ読み込む
},
```

`createGame()` が返すオブジェクトのライフサイクル（`src/core/gameManager.js` が呼び出します）:

| メソッド | 呼ばれるタイミング |
|---|---|
| `start(context)` | 生成直後。`context.container` に DOM/Canvas を作る |
| `update(dt)` | 固定時間ステップ（60Hz）。ホストは正本を進め、ゲストは入力送信・予測など |
| `render(alpha, frameDt)` | requestAnimationFrame ごと |
| `onMessage(message)` | ホスト: `{ type: 'player_input', seq, inputs }` / 双方: `{ type: 'game_msg', data }` |
| `getSnapshot()` | ホスト: シリアライズ可能な状態を返す（毎秒20回配信・切断時の保持に使用） |
| `loadSnapshot(snapshot)` | 再接続・一時停止時の完全復元 |
| `applyNetSnapshot(snap, events)` | ゲスト: 定期配信の受信 |
| `drainNetEvents()` | ホスト（任意）: 前回配信以降の演出イベント |
| `encodeNetSnapshot(snap)` | ホスト（任意）: 定期配信用に小さく詰める（ゲストの `applyNetSnapshot` で戻す） |
| `pause()` / `resume()` | 一時停止・再開 |
| `end()` / `destroy()` | 終了・3Dオブジェクトやリスナーの解放 |

`context` の主な中身: `role`（'host' / 'guest'）, `isHost`, `playerIndex`（ホスト0・ゲスト1）, `container`, `input`（キーボード）, `sound`（効果音）, `music`（BGM）, `options`（準備画面の設定）,
`sendInput(seq, inputs)`（ゲスト→ホスト）, `sendGameMessage(data)`, `finish(result)`（ホストのみ・勝敗確定）, `getNetInfo()`。

`finish(result)` に渡す結果は次の形にすると、共通の結果画面にそのまま表示されます。

```js
{
  gameId: 'quiz',
  winner: 'host',            // 'host' | 'guest' | null
  title: '柴犬の勝ち！',
  host:  { headline: '🏆 1位', detail: '5問正解' },
  guest: { headline: '2位',   detail: '3問正解' },
  stats: [{ label: '正解数', host: '5', guest: '3' }],
}
```

## 9. 接続できない場合の確認事項

- ホストのページが開いたままか（ホストが更新・終了すると部屋はなくなります）
- 招待URLが途中で切れていないか（`room=` と `key=` の両方が必要）
- すでに別の人がゲストとして参加していないか（ゲスト枠は1つ）
- 会社・学校・公衆Wi-Fi、一部のモバイル回線（キャリアグレードNAT）では WebRTC の P2P 接続が通らないことがあります。
  PeerJS の既定設定には PeerJS 提供の公開 TURN サーバーが含まれますが、可用性は保証されていません。
  確実に接続したい場合は、「Cloudflare の中継で通信する」の手順で中継を設定してください
- 広告ブロッカー・VPN・セキュリティソフトが WebRTC や `0.peerjs.com` への接続を止めていないか
- PeerJS Cloud が一時的に混雑・停止している可能性もあります（時間をおいて再試行）
- ブラウザの開発者ツールのコンソールにエラーが出ていないか

## 10. 現在の制限事項

- プレイヤーは2人固定。観戦・3人以上は非対応
- ホストのページ更新・終了からの復帰は非対応（仕様）。ゲストもタブを閉じた後の復帰は保証しません（sessionStorage のため）
- Cloudflare の中継は任意の設定です。設定しない場合、ネットワーク環境によっては P2P がつながりません。中継はローカルの Worker（wrangler dev）での確認までで、実際の Cloudflare 上での動作・各種ネットワークでの接続は未確認です
- ゲストの車はクライアント予測で動かし、ホストの確定状態に少しずつ合わせています。
  遅延が大きいと、体当たり・被弾の瞬間に位置が補正されることがあります
- 通信遅延のぶん、ゲスト画面のホストの車は約0.1秒＋遅延だけ過去の位置を表示しています
- スマートフォン・タブレットのタッチ操作に対応していますが、実機での検証は限られています（描画が重い端末では自動で画質を下げます）。コースが大きくなったぶん、古い端末では背景が簡素になります
- 招待URLを知っている人はゲスト枠が空いているときに参加できます。信頼できる相手との2人プレイ向けで、強固な認証の代わりにはなりません
- 収録ゲームは「わんわん爆走カート」1本、コースは10種類です。最大7台（人間2 + NPC 4 + ボス犬1）
- NPC はホストのブラウザで計算します（ホストの端末が遅いと NPC も含めて動きが重くなります）

## 通信と軽量化の工夫

- ゲーム更新はホストで 60Hz、位置の配信は毎秒30回（ドッグフードは「いま取られている番号の一覧」だけを送ります）
- コース上の位置の検索（壁・周回・順位の判定で毎フレーム大量に呼ばれます）は、コースを格子に区切って近くの区間だけ調べます。結果は全探索と同じです（単体テストで確認）
- P2P の接続を2本使います。部屋の状態・一時停止などの制御は「順序保証あり」の接続、
  位置の定期配信とゲストの入力は「順不同」の高速接続（`reliable: false`）で送り、1つのパケットの遅れで後続が詰まらないようにしています。
  高速接続が開けない環境では自動的に通常の接続で送ります
- 定期配信はキー名を省いた配列形式に詰めて送信量を減らしています。演出イベントには ID を付けて3回続けて載せ、ゲスト側で重複を除きます
- ゲストの入力は直近8 tick 分を毎回重ねて送るので、1通落ちても欠けません
- 大きなコースでも重くならないよう、背景（木・小物）は区画ごとに別のメッシュにして見えない区画は描かず、コースの壁は近くだけ丸い形・遠くは四角い形にしています
- 描画が重い端末では、自動で解像度 → 影 → さらに解像度の順に画質を下げます（描画解像度は最大1.5倍）
- タイミングブーストのリングは、ゲストは自分の車の予測で表示し、判定はホストが「その車がチャンス地点を通ってからの時間」で行います。
  ホストはゲストの入力を届いた順に 1 tick ずつ適用するので、通信の遅れがあってもゲストの画面で見たタイミングどおりに判定されます。
  飼い主登場中の自分の車は自動で走るので、ゲストでも予測せずホストの状態をそのまま表示します（操作を受け付けないため）。
  ただし通信が大きく揺れたときは判定が少しずれることがあります

## 通信プロトコル（概要）

すべて `{ type, ... }` の JSON。受信側で方向・形式・サイズ・値域を検証し、不正なものは捨てます。

- 入室: `join_request` → `join_accepted` / `join_rejected`
- 部屋: `room_state`（画面遷移を含む部屋の正本。`screen_change` の役割も兼ねる）, `ready_change`
- ゲーム: `game_start`（初回・再接続時の完全同期）, `player_input`（seq 付き）, `game_snapshot`（毎秒30回）, `game_msg`, `game_result`, `game_abort`
- 一時停止: `pause`（状態付き）→ `resume_ack` → `resume`（カウントダウン）
- 終了: `room_close`, `leave`（ゲスト退出）, `bye`（ページ終了の補助通知）
- 生存確認: `ping` / `pong` / `presence`

試合ごとの `matchId` と、一時停止・再同期のたびに増える世代番号 `gen` で、古い試合や古い世代のメッセージを無視します。
